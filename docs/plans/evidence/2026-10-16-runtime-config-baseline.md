## Open Question 2: Management compatibility and `/users/current`

Source: netbird-server fork (v0.80.0 base).
- `/api/users/current` exists since v0.41.x (#3666, April 2025). Older
  Management answers 404 (405 behind some proxies): that is the only signal for
  the `users.find(u => u.is_current)` fallback.
- Provisioning (#366): the HTTP auth middleware calls `ensureAccount` on **every**
  authenticated request, so `/users/current` provisions the account and user on
  first login exactly as `GET /users` did. The `/users` warm-up gate is not
  needed; `/users/current` goes out first and alone (lists wait for it), with
  transient retries (network/5xx, 3x, 500 ms backoff).
- `GetCurrentUserInfo`: pending approval → 403 "… pending approval [by owner …]";
  blocked → 403 "user is blocked"; older builds report pending as blocked on
  `/users/current` while the list still says pending — kept via
  `resolveRefusedUser`, which still reads the list error.

## Open Question 4: production topology

Compose project `netbird`; one `netbird-dashboard` container (built
`FROM netbirdio/dashboard:latest`), plus `netbird-server` (0.80.0 + custom
binary) and Traefik v3.7. Unlike the local deploy notes, prod bind-mounts
the dashboard `html/` directory over `/usr/share/nginx/html` **read-write**. Entrypoint is
supervisord running the **official** `init_react_envs.sh` (same as the repo
version minus the robots block); nginx.conf identical to the repo's (md5
`4005943f…`). Traefik: labels only, no cache middleware; single replica.
Releases dir keeps 5 (~23 MB each). Server has jq, python3, rsync, curl,
Docker Compose v2; enough free disk.
The production CSP generated by the new generator equals the live one except
that `https://none` / `wss://none` (from `LETSENCRYPT_DOMAIN=none`) are gone.

## Open Question 5: AUTH_CLIENT_SECRET

Decision (ethan): ignore it and log a warning at start. Prod has it empty.

sends `client_secret` (public SPA client with PKCE).
