# Translations (i18n)

## Scope

This file applies to `src/i18n/` and to every change that adds or edits
user-visible text anywhere under `src/`. The repo-wide rules in the root
`AGENTS.md` still apply; for translation work this file is more specific
and takes precedence.

## How it works

- `src/i18n/index.ts` sets up i18next client side only, because
  `next.config.js` builds a static export. There is no locale in the URL.
- Languages: `en` (source of truth, bundled) and `zh-CN` (loaded per
  namespace on demand). Missing keys fall back to `en`.
- Language order: localStorage key `netbird-lang`, then the browser language,
  then the build-time `NEXT_PUBLIC_DEFAULT_LANG`, then `en`
  (`src/i18n/config.ts`). The switcher in `src/i18n/LanguageSwitcher.tsx`
  stores the choice and reloads the page.
- `common`, `nav` and `components.*` load at start
  (`src/i18n/I18nProvider.tsx`). A route loads its module namespaces through
  `src/i18n/NamespaceGate.tsx` in its `layout.tsx`.
- Known English API errors map to keys in `src/i18n/apiErrors.ts`; unknown
  messages are shown as they are.

## Where translations live

- One flat JSON file per namespace, in the `en` and `zh-CN` folders under
  `src/i18n/locales`, with the same file names and keys in both folders.
- A namespace is `module.feature`, for example `peers.main`, `peer.page`,
  `settings.authentication-tab`; shared UI is `components.ui` and friends.
- Size cap per file: 150 keys and 12 KB. When a file would pass the cap,
  split it by feature; do not grow it.
- Shared words (Save, Cancel, Delete) live in `common` as `word.*`; reuse
  them instead of adding a copy to a module namespace.

## Adding or changing text

1. Add the key to the `en` file, then the same key to `zh-CN`. Never change
   one language only.
2. Keys are flat: `{area}.{element}.{purpose}`, for example
   `setupKeysTable.text.createKey`. Do not use the English text as the key.
3. In code: `import { t } from "@/i18n";` then
   `t("setup-keys.main:setupKeysTable.text.createKey")`. Keys are typed by
   `src/i18n/resources.generated.d.ts`, so a typo fails the type check.
4. Interpolation wraps the variable in double curly braces, with the same
   variable names in both languages. Never build sentences by joining strings.
5. Only call `t()` while rendering or in handlers, never in module-level
   constants: those are evaluated before the language is known.
6. Use the glossary below. Keep NetBird, WireGuard, SSO, IdP, MFA, OIDC,
   CIDR, JWT, API and DNS in English.

## Translating one module

1. List what is still hardcoded:
   `I18N_LIST=1 npm run i18n:extract -- --dry src/modules/dns`.
2. Run the codemod on that folder only:
   `npm run i18n:extract -- src/modules/dns`. It rewrites literals to `t()`
   and fills `en` (and `zh-CN` with English placeholders).
3. Translate the new `zh-CN` values, add a `NamespaceGate` module entry in
   the route's `layout.tsx`, and fix sentences the codemod split.
4. One module per commit; change nothing except the text.
5. Module-level constants: list them with `I18N_MODULE_LEVEL=1 I18N_LIST=1`,
   then run the codemod with `--getters` so each property becomes a getter
   that calls `t()` at render. Add `--getters-all` for plain message maps.
6. Never translate strings that are compared, sent to the API, used as ids,
   or sent to analytics. Undo a wrong extraction with
   `node scripts/i18n/revert-keys.mjs ns:key ... -- <files>`.
7. Browser tab titles go through `src/i18n/pageTitle.ts` (`titles`
   namespace); leave the `metadata` exports in English.

## Checks before completion

- `npm run i18n:types` regenerates `src/i18n/resources.generated.d.ts` and
  `src/i18n/namespaces.generated.ts`; never edit those files by hand.
- `npm run i18n:check`: key parity, missing and unused keys, size cap,
  interpolation variables, and untranslated `zh-CN` values.
- Lint the changed files (`npx eslint src/modules/dns`), run
  `npx vitest run src/i18n` and `npx tsc --noEmit`.

## Safety

- Do not delete keys that other modules still use; `npm run i18n:check`
  lists unused keys.
- Never put secrets, tokens or customer data in locale files.
