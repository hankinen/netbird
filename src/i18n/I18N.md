# Translations (i18n)

## Scope

This file applies to `src/i18n/` and to every change that adds or edits
user-visible text anywhere under `src/`. The repo-wide rules in the root
`AGENTS.md` still apply; for translation work this file is more specific
and takes precedence.

## How it works

- Library: `react-i18next`, client side only, because `next.config.js`
  builds a static export (`output: "export"`). There is no locale in the URL.
- Languages: `en` (source of truth) and `zh-CN`. Missing keys fall back to `en`.
- Language order: the `netbird-lang` localStorage value, then the browser
  language, then `NEXT_PUBLIC_DEFAULT_LANG`, then `en`.
- Namespaces `common` and `nav` load at start; every other namespace is
  loaded lazily by the page that uses it.

## Where translations live

- One JSON file per namespace, in the `en` and `zh-CN` folders under
  `src/i18n/locales`, with the same file names and keys in both folders.
- Name a namespace `module.feature` (`peers.list`, `peers.detail`,
  `settings.auth`). A small module uses one namespace named after it (`groups`).
- Size cap per file: 150 keys and 12 KB. When a file would pass the cap,
  split it by feature; do not grow it.
- Shared words (Save, Cancel, Delete, Online) go in `common` only; never
  repeat them in a module namespace.

## Adding or changing text

1. Add the key to the `en` file of the namespace, then the same key to
   `zh-CN`. Never change one language only.
2. Keys are flat, dot separated: `{area}.{element}.{purpose}`, for example
   `table.column.name`, `toast.delete.success`, `modal.delete.title`.
   Do not use the English text as the key.
3. In components: `const { t } = useTranslation("peers.list")`, then
   `t("table.column.name")`. Keys and namespaces are typed, so a typo fails
   the type check.
4. Interpolation wraps the variable in double curly braces, with the same variable names in both
   languages. Plurals use the `_one` and `_other` suffixes (zh-CN only needs
   `_other`). Text with links or bold uses `<Trans>`.
5. Never build sentences by joining strings; give the whole sentence one key.
6. Use the Chinese terms from the glossary below. Keep NetBird, WireGuard,
   SSO, IdP, MFA, OIDC, CIDR, FQDN, API and DNS in English.

## Translating one module

Work on one module per commit: read this file, open only that module's
folder and its locale files, replace literal text with `t()` calls, fill
`en` and `zh-CN`, then run the checks below. Change nothing except the
text, so the fork stays easy to rebase on upstream.

## Checks before completion

- `npm run i18n:types` regenerates `src/i18n/resources.generated.d.ts`;
  never edit that file by hand.
- `npm run i18n:check` checks key parity between `en` and `zh-CN`, missing
  and unused keys, the size cap, and matching interpolation variables.
- Then lint the changed files (`npx eslint src/modules/peers`) and run
  `npx tsc --noEmit`.

## Safety

- Do not delete keys that other modules still use; `npm run i18n:check`
  lists unused keys.
- Never put secrets, tokens or customer data in locale files.
